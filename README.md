# 인디밴드 키우기

> 태교에서 첫 기타, 밴드부에서 첫 EP, 무명에서 록스타까지.
> 실제 통계와 선택, 인간관계, **실제로 들리는 노래**로 만들어지는 한 음악가의 일생.

“밴드부 친구랑 만든 첫 곡이 20년 뒤 역주행했습니다.”

**▶ 바로 플레이: https://rkdmin.github.io/indie-band-life/** (설치 없이 PC·휴대폰 브라우저에서)

## 어떻게 플레이하나

1. **태어나기** — 어디서, 어떤 집에서 태어날지는 고를 수 없다. 카세트 J카드에 그해 실제 출생아 수·기대수명, **타고난 재능·성격**, 실제 통계로 굴린 **인생 변수**(형제·쌍둥이·다문화 가정·부모님 직업·이혼·조부모·반려동물·절대음감·왼손잡이…)와 **이렇게 태어날 확률**이 찍힌다.
2. **시간이 흐른다** — 인생이 실시간으로 흘러간다. 기본 ‘약 1시간’ 설정에서 스무 살 무렵 1년 ≈ 55초 (30분·1시간 30분 선택 가능). 멈춤 · 1×~8× · ‘다음 결정까지’ 빨리 감기.
3. **생활 계획** — 연습·합주·작곡·알바 같은 계획을 정해 두면 바꿀 때까지 그렇게 산다. ‘알아서’에 맡겨도 된다.
4. **갈림길과 턴테이블** — 사건이 오면 시간이 멈춘다. 위험한 선택은 **바늘 판정**: LP에 1~20번 트랙이 원처럼 새겨져 있고 성공하는 트랙이 미리 칠해져 있다(확률이 눈에 보인다). 판을 **손으로 돌렸다 놓으면** 바늘이 내려앉은 트랙이 판정 값 — 20번 히든 트랙은 대성공, 1번은 판이 튄다. 계산은 d20 + 보정치 ≥ 난이도와 같다. 실패하면 **영감(✦)** 으로 B면을 한 번 더 튼다.
5. **큰 순간은 전체 화면** — 출생, 밴드부 오디션, 첫 무대, 발매(그 곡이 실제로 재생된다), 해외 무대, 마지막 무대.
6. **부고** — 일생이 신문 부고 한 문단으로 남고, 대표곡이 흐른다. 카드로 공유할 수 있다.

## 다른 컴퓨터에서 실행하기

필요한 것: **Node.js 20 이상** (https://nodejs.org) 과 Git.

```bash
git clone https://github.com/rkdmin/indie-band-life.git
cd indie-band-life
npm install
npm run dev        # 브라우저에서 http://localhost:5180
```

빌드된 버전만 띄우려면 (Node 만 있으면 된다):

```bash
npm run build
npx serve dist     # 또는 GitHub Releases 의 indie-band-life-web.zip 을 풀고 그 폴더에서 npx serve
```

같은 와이파이의 휴대폰에서 해 보려면 `npm run dev -- --host` 후 표시되는 네트워크 주소로 접속한다.

### Android 앱 (Capacitor)

`capacitor.config.json` — appId `app.indieband.life`, appName `인디밴드 키우기`, webDir `dist`.
`android/` 는 저장소에 포함되어 있다. 빌드에는 Android Studio(JDK 21 + Android SDK)가 필요하다.

```bash
npm run cap:sync   # 웹 빌드 후 dist/ 를 android/ 로 복사 (npm run build && npx cap sync android)
npx cap open android   # Android Studio 에서 실행 / 서명된 .aab 생성
```

네이티브 기능은 `src/platform.ts` 한곳에 있고 모두 웹 폴백을 가진다.

| 기능 | 앱 | 웹 |
|---|---|---|
| 엔딩 인생 카드 공유 | `@capacitor/share` (캐시에 PNG 저장 후 공유 시트) | Web Share API, 미지원 시 다운로드 + 문구 복사 |
| 곡 WAV 저장 | 공유 시트로 저장 위치 선택 (저장소 권한 불필요) | `a[download]` |
| 하드웨어 뒤로가기 | 맨 위 시트 닫기 → 만들기/도감이면 타이틀로 → 그 외엔 앱 최소화 | 해당 없음 (시트는 Esc 로 닫힘) |

## 배포

`.github/workflows/deploy.yml` 이 `main` 푸시·PR 마다 `npm run verify` 를 돌린다.
`main` 푸시에서는 `dist/` 를 GitHub Pages 로 배포하는데, **저장소 변수 `PAGES_ENABLED=true` 가 있을 때만** 배포 잡이 돈다.

Pages 켜는 법:
1. Settings → Pages → Source 를 **GitHub Actions** 로 바꾼다 (비공개 저장소는 유료 플랜이 필요).
2. Settings → Secrets and variables → Actions → Variables 에 `PAGES_ENABLED` = `true` 추가.
3. `main` 에 푸시하거나 Actions 탭에서 워크플로를 수동 실행한다.

`vite.config.ts` 의 `base: './'` 덕분에 `https://<계정>.github.io/<저장소>/` 같은 하위 경로에서도 그대로 동작한다.
Vercel 을 쓰려면 Framework preset `Vite`, Build `npm run build`, Output `dist` 로 연결하면 된다.

## 기획서 대비 바꾼 결정

| 기획서 | 이 구현 | 이유 |
|---|---|---|
| Expo + React Native Web | **Vite + React + TypeScript (PWA)** | 웹 우선 출시가 1순위 단계이고, 개발·검증 속도가 압도적. 시뮬레이션 코어가 순수 TS라 이후 Capacitor/Expo로 감싸도 그대로 재사용된다 |
| 외부 AI 음악 API (Suno 등) | **자체 절차적 작곡 엔진 (Web Audio)** | 공식 API·배포권이 불확실하고(기획서 8장 경고), 유저당 원가가 0원이 된다. `compose(seed, genre, mood, quality)` 인터페이스는 나중에 외부 공급자 어댑터로 교체 가능 |
| AI 생성 일러스트 | **코드로 그린 레이어드 SVG 장면 + 결정적 아바타** | 저작권·일관성 문제 없음. 같은 인물은 평생 같은 얼굴로 나이 든다 |
| Supabase 서버 저장 | **로컬 저장 (localStorage)** | MVP는 회원가입 없이 바로 플레이 (기획서 14장 “공개 웹 베타: 회원가입 없이 체험”) |
| 사건 JSON | **TypeScript 함수형 사건 정의** | 조건·확률·결과 텍스트를 타입 안전하게 표현. 상태 자체는 JSON 직렬화 가능 |

추가한 것: 병역 시스템, 시대 사건(2020 공연장 폐쇄·밴드 붐), 역주행, 레이블 딜레마, 진정성 보너스, 엔딩 랭크, 엔딩 도감.

## 데이터 고치기·늘리기

데이터는 전부 `src/data/**/*.json` 에 있다. 코드를 몰라도 JSON 한 줄을 더하면 게임에 바로 반영된다.

| 하고 싶은 일 | 고칠 파일 | 예 |
|---|---|---|
| 실존 밴드 추가 | `era/bands.json` | `{"name": "새 밴드", "c": "KR", "from": 2012, "to": 2025, "genres": ["indierock"]}` → 그 기간에 클럽 포스터·오프닝·라디오·공연 사건이 자동으로 생긴다 |
| 음악사 사건 추가 | `history/<나라>.json` | `y`·`m`·`kind`·`text`·`src`(출처 필수). 발매(`release`)에 장르를 달면 `who` 도 필요 |
| 시대에 없던 말 추가 | `era/terms.json` | `{"pattern": "말", "y": 2010, "old": [[1990, "그 전 말"], [0, null]]}` — `null` 은 그 문장을 뺀다 |
| 장르·매체 연도 조정 | `era/genres.json`, `era/media.json` | 나라별 연도 |
| 시대의 일상 추가 | `era/life.json` | 연도 범위·나라·나이 |

고친 뒤 `npm test` 를 돌리면 세 겹으로 검사한다:
- `tests/data.test.ts`: JSON 모양 — 나라 코드·장르 값·연도·출처·중복·정규식·확률 합계·시대 구분의 빈틈
- `tests/history.test.ts`: 1950~90년대생 인생 전체에 시대에 없던 말·장르가 나오는지, 실존 밴드가 활동 기간 밖에 나오는지
- `tests/ending_odds.test.ts`: 엔딩·배지 빈도 데이터가 빠짐없는지 (기준을 바꾸면 `GEN_ODDS=1` 로 다시 만든다)
- `tests/systems.test.ts`: 생활 계획 고르기(한 번 누르면 하나만, 칸이 차면 알림), 잠긴 계획이 실행되지 않는지, 선택지 회전, 반복 감쇠, 컷신 반응
- `tests/breakout.test.ts`: 길의 운영 기간·매체 연도, 어린이 기록에 음악 소식·발매·계약이 없는지, 용돈·열아홉 살 돈, 잠긴 선택지는 이유가 보이고 고를 수 없는지
- `tests/logic.test.ts`: NaN·음수 팬·죽은 뒤 기록·죽은 멤버·나이에 맞지 않는 사건·외국인 병역, 출생 변수끼리의 모순(겹치면 안 되는 특징·장면, 나라·달·장소 조건)과 인생마다 다르게 태어나는지

## 원칙

- 내 인생의 인물·밴드·곡은 모두 가상이다. 실존 밴드는 실명으로 나오되 세 가지를 지킨다:
  1. **텍스트로만** — 초상·로고·앨범 커버·음원을 쓰지 않는다.
  2. **말이나 행동을 지어내지 않는다** — 문장은 언제나 ‘내가’ 겪은 일이다(같은 포스터에 이름이 올랐다, 오프닝 무대에 섰다, 맨 앞에서 공연을 봤다). 실제 활동 기간·실제 라인업에만 배치한다.
  3. **홍보에 쓰지 않는다** — 스토어 설명·광고·공유 이미지 문구에 실존 밴드 이름을 내세우지 않는다.
- 실제 통계·근사·게임 가정을 코드와 문서에 구분해 표기한다 (`[통계]` `[근사]` `[가정]`).
- 가난·지역·장르를 본질적으로 불리하게 고정하지 않는다. 장르는 기회와 관객을 바꿀 뿐 건강·사고를 결정하지 않는다.
- 같은 시드 + 같은 선택 → 같은 인생 (결정적 PRNG, 테스트로 보장).
