# 인디밴드 키우기

> 태교에서 첫 기타, 밴드부에서 첫 EP, 무명에서 록스타까지.
> 실제 통계와 선택, 인간관계, **실제로 들리는 노래**로 만들어지는 한 음악가의 일생.

“밴드부 친구랑 만든 첫 곡이 20년 뒤 역주행했습니다.”

## 무엇이 들어 있나

| 시스템 | 내용 |
|---|---|
| 생애 | 태교 → 영유아 → 초·중·고 → 20대 → 30대 → 중년 → 노년. 나이에 따라 시간 흐름이 다르다 (어릴 땐 몇 년씩, 청춘은 반년씩, 노년은 2년씩) |
| 인연 | 모든 인물이 영구 ID·나이·악기·성격·꿈·기억을 가진다. 세 살 어린이집 단짝이 서른에 드러머로 돌아오고, 중학교 친구가 마흔에 프로듀서가 되어 연락한다 |
| 밴드 | 결성·멤버 모집·합주·팀워크·탈퇴·해체·재결합, 인디 레이블/대형 기획사 계약 |
| 작곡 | 인생에서 겪은 일이 곡의 주제가 된다(첫사랑·입대·이별·상실…). 직접 겪은 주제는 진정성 보너스 |
| **음악** | 모든 곡이 시드 기반 절차적 작곡기로 **실제 재생**된다. 장르별 편성·템포·톤, 품질이 높을수록 훅이 반복되고 코드톤에 착지한다. WAV로 저장 가능 |
| 공연 | 오픈마이크 → 클럽 → 소극장 → 지역/대형 페스티벌 → 아레나. 관객 실루엣·조명이 움직인다 |
| 한국적 디테일 | 수능·실용음악과 입시, **병역**(군악대 오디션·입영 연기), 상경과 반지하 독립, 명절 잔소리, 2020년 공연장 폐쇄, 2020년대 밴드 붐 |
| 건강 | 수면·과로·흡연·음주의 장기 영향. 위험 행동을 미화하지 않고, 단번에 죽이지 않는다 |
| 엔딩 | 12종: 전설 · 불꽃처럼 · 역주행 · 컬트 레전드 · 원 히트 원더 · 다시, 우리 · 평생 현역 · 다음 세대의 등불 · 바닥에서 부른 노래 · 마음속 밴드 · 행복한 아마추어 · 라디오를 켜 두는 사람 + S~C 랭크 |
| 공유 | 엔딩 때 1080×1350 인생 카드 이미지 생성 → 공유 시트 또는 저장 |
| 재플레이 | 엔딩 도감, 지난 인생 목록 |

사건 115개 이상(스토리 31 · 인생/관계 37 · 밴드/업계/건강 47), 장면 16종, 무드 6종, 장르 6종.

## 실행

```bash
npm install
npm run dev        # http://localhost:5180
npm run verify     # 타입체크 + 테스트 + 빌드
npm run balance    # 자동 플레이 600회 밸런스 리포트
```

## 기획서 대비 바꾼 결정

| 기획서 | 이 구현 | 이유 |
|---|---|---|
| Expo + React Native Web | **Vite + React + TypeScript (PWA)** | 웹 우선 출시가 1순위 단계이고, 개발·검증 속도가 압도적. 시뮬레이션 코어가 순수 TS라 이후 Capacitor/Expo로 감싸도 그대로 재사용된다 |
| 외부 AI 음악 API (Suno 등) | **자체 절차적 작곡 엔진 (Web Audio)** | 공식 API·배포권이 불확실하고(기획서 8장 경고), 유저당 원가가 0원이 된다. `compose(seed, genre, mood, quality)` 인터페이스는 나중에 외부 공급자 어댑터로 교체 가능 |
| AI 생성 일러스트 | **코드로 그린 레이어드 SVG 장면 + 결정적 아바타** | 저작권·일관성 문제 없음. 같은 인물은 평생 같은 얼굴로 나이 든다 |
| Supabase 서버 저장 | **로컬 저장 (localStorage)** | MVP는 회원가입 없이 바로 플레이 (기획서 14장 “공개 웹 베타: 회원가입 없이 체험”) |
| 사건 JSON | **TypeScript 함수형 사건 정의** | 조건·확률·결과 텍스트를 타입 안전하게 표현. 상태 자체는 JSON 직렬화 가능 |

추가한 것: 병역 시스템, 시대 사건(2020 공연장 폐쇄·밴드 붐), 역주행, 레이블 딜레마, 진정성 보너스, 엔딩 랭크, 엔딩 도감.

## 구조

```
src/
  sim/            순수 TS 시뮬레이션 (브라우저 의존 없음, 테스트 가능)
    engine.ts       턴 흐름: newGame → submitActions → choose → proceed → ending
    actions.ts      매 시기 행동 (연습·작곡·합주·공연·발매·알바…)
    events/         story.ts(뼈대) life.ts(인생·관계) career.ts(밴드·업계·건강)
    ctx.ts          사건이 상태를 바꾸는 도우미 (조사 처리·확률·기록)
    songs.ts        곡 주제·가사·품질·발매·역주행
    endings.ts      엔딩 판정과 랭크
    data/world.ts   최저임금·생명표 근사·인구 분포·시대·장르·공연장
  audio/          compose.ts(작곡기) synth.ts(신시사이저) player.ts(재생·효과음·WAV)
  art/            Avatar · Scene · Cover (SVG)
  ui/             화면
tests/            엔진·작곡기 테스트 + 자동 플레이 밸런스
docs/             probability-sources.md (통계 출처와 가정)
```

## 원칙

- 실존 연예인·밴드·곡·방송·브랜드 이름을 쓰지 않는다. 모든 인물과 이름은 가상이다.
- 실제 통계·근사·게임 가정을 코드와 문서에 구분해 표기한다 (`[통계]` `[근사]` `[가정]`).
- 가난·지역·장르를 본질적으로 불리하게 고정하지 않는다. 장르는 기회와 관객을 바꿀 뿐 건강·사고를 결정하지 않는다.
- 같은 시드 + 같은 선택 → 같은 인생 (결정적 PRNG, 테스트로 보장).
